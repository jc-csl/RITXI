INSTRUCCIONES - PRUEBA LOCAL LLM REACHY MINI CON UV
====================================================
https://github.com/dwain-barnes/reachy_mini_conversation_app_local

Objetivo
--------
Hacer una prueba independiente del fork local de la aplicación de conversación de Reachy Mini,
usando un entorno virtual propio con uv y Ollama local.

IMPORTANTE:
- Esta prueba NO toca Ahootsa.
- Esta prueba NO toca el entorno oficial de Reachy Mini Control.
- Esta prueba NO toca:
  C:\Users\Alumno\AppData\Local\Reachy Mini Control\apps_venv
- Todo se instala aparte en:
  D:\RITXI\pruebas_local_llm


REQUISITOS PREVIOS
------------------

Debes tener instalado:

1. Git
2. uv
3. Ollama
4. Python 3.12
5. Reachy Mini Control / daemon funcionando para MuJoCo

Comprobar uv:

    uv --version

En caso de necesitar instalar uv en Powershell:oll
powershell -ExecutionPolicy ByPass -c "irm https://astral.sh/uv/install.ps1 | iex"

Comprobar Git:

    git --version

Comprobar Ollama:

    ollama --version

Comprobar modelos disponibles en Ollama:

    ollama list

Actualizar los modelos descargados de Ollama:
ollama list | Select-Object -Skip 1 | ForEach-Object { $model = ($_ -split '\s+')[0]; ollama pull $model }

En tu equipo ya aparece disponible:

    llama3.2:3b

Por eso usaremos ese modelo para la primera prueba.


PASO 1 - CERRAR AHOOTSA
-----------------------

Antes de probar la app local, conviene cerrar Ahootsa porque normalmente usa el puerto 7860.

Ejecuta:

    cd D:\RITXI\7_0_23_ahootsa_base_terminal_limpio_boton_salir
    powershell -ExecutionPolicy Bypass -File .\PARAR_AHOOTSA_7_0_23.ps1

Si el daemon o MuJoCo siguen abiertos, pueden quedarse abiertos.
Lo importante es que no esté corriendo otra app en:

    http://127.0.0.1:7860


PASO 2 - CREAR CARPETA INDEPENDIENTE
------------------------------------

Crear carpeta para la prueba local:

    mkdir D:\RITXI\pruebas_local_llm -Force
    cd D:\RITXI\pruebas_local_llm


PASO 3 - CLONAR EL FORK LOCAL
-----------------------------

Clonar el repositorio comunitario local:

    git clone https://github.com/dwain-barnes/reachy_mini_conversation_app_local.git
    cd .\reachy_mini_conversation_app_local

Si ya existía una copia y quieres empezar limpio:

    git clone https://github.com/dwain-barnes/reachy_mini_conversation_app_local.git
    cd .\reachy_mini_conversation_app_local


PASO 4 - CREAR ENTORNO VIRTUAL CON UV
-------------------------------------

Crear entorno virtual propio con Python 3.12:

    uv venv --python 3.12

Activar el entorno:

    .\.venv\Scripts\Activate.ps1

Debes ver algo similar al principio de la línea:

    (.venv) PS D:\RITXI\pruebas_local_llm\reachy_mini_conversation_app_local>


PASO 5 - INSTALAR DEPENDENCIAS CON UV
-------------------------------------

Instalar el fork dentro de este entorno virtual:

    uv pip install --upgrade pip setuptools wheel
    uv pip install -e "."

La app local importa AsyncOpenAI igualmente al arrancar, aunque luego uses Ollama. La librería openai no se ha instalado como dependencia automática.
    uv pip install openai

Actualizar SDK Reachy Mini dentro del venv local
    uv pip install --upgrade "reachy-mini==1.8.4"
Comprobar:
    uv pip show reachy-mini

Otra dependiencia que pide en las pruebas realizadas:
    uv pip install torchaudio

La instalación recomendada para usar TTS con FastRTC es instalarlo con extras de voz/TTS, no solo el paquete base:
    uv pip install "fastrtc[vad,stt,tts]"

Comentario:
- Esta instalación queda dentro de:
  D:\RITXI\pruebas_local_llm\reachy_mini_conversation_app_local\.venv
- No modifica Ahootsa.
- No modifica apps_venv de Reachy Control.

Cuando instalas la app del robot con el comando pip install -e ".", estás usando una función especial de setuptools y wheel llamada Editable Install.
A veces, para proyectos de robótica o IA (como MuJoCo o bindings de audio de Reachy), te descargarás un archivo .whl específico desde un repositorio o un release de GitHub. Para instalarlo directamente en tu entorno usas:
PowerShell
uv pip install ruta/al/archivo_paquete.whl
En lugar de empaquetar un archivo .whl fijo y moverlo a las carpetas ocultas de Python, este comando crea un "enlace simbólico" hacia tu carpeta D:\RITXI\.... De esta forma, cualquier cambio que hagas en los archivos .py del código del robot se aplica al instante sin necesidad de volver a instalar nada.


PASO 6 - NO INSTALAR VISIÓN LOCAL TODAVÍA
-----------------------------------------

Para la primera prueba de rendimiento, NO instalar visión local.

No ejecutes todavía:

Eso lo dejaremos para una segunda fase, porque descarga dependencias más pesadas
como torch/transformers/modelos visuales.


PASO 7 - CREAR ARCHIVO .ENV
---------------------------

Crear o editar el archivo:

    D:\RITXI\pruebas_local_llm\reachy_mini_conversation_app_local\.env

Abrir con Notepad:
	copy .env.example .env
        notepad .env
FULL_LOCAL_MODE=true
JETSON_OPTIMIZE=false

LLM_PROVIDER=ollama
OLLAMA_ENDPOINT=http://localhost:11434/v1
OLLAMA_MODEL=phi3:latest

DISTIL_WHISPER_MODEL=distil-whisper/distil-small.en
WHISPER_LANGUAGE=en

KOKORO_VOICE=af_sarah
KOKORO_SPEED=1.0

VAD_ENERGY_THRESHOLD=0.015
VAD_SILENCE_DURATION=0.8
VAD_MIN_SPEECH_DURATION=0.3

ONNX_PROVIDERS=CPUExecutionProvider

HF_HOME=./cache
HF_TOKEN=

Para probar en español después de ver rendimiento en ingles, cambia a algo así:

DISTIL_WHISPER_MODEL=distil-whisper/distil-large-v3
WHISPER_LANGUAGE=es


Guardar y cerrar.

Comentario:
- LLM_PROVIDER=ollama indica que el cerebro será Ollama local.
- OLLAMA_MODEL=llama3.2:3b usa el modelo que ya tienes instalado.
- DISTIL_WHISPER_MODEL configura el STT local.
- KOKORO_VOICE configura la voz TTS local.
- JETSON_OPTIMIZE=false porque estás en PC Windows, no Jetson.

PASO 9 - COMPROBAR DAEMON / MUJOCO
----------------------------------

Con Reachy Mini Control abierto o el daemon arrancado, comprobar:

    Invoke-WebRequest http://127.0.0.1:8000/api/daemon/status

Debe devolver respuesta correcta, normalmente HTTP 200.

Comentario:
- El daemon/MuJoCo va por el puerto 8000.
- La app de conversación va por el puerto 7860.
- Ollama va por el puerto 11434.

PASO 9.1 - ARRANCAR EL DAEMON MUJOCO
----------------------------------
cd D:\RITXI\pruebas_local_llm\reachy_mini_conversation_app_local
.\.venv\Scripts\Activate.ps1
$Daemon = "$env:LOCALAPPDATA\Reachy Mini Control\apps_venv\Scripts\reachy-mini-daemon.exe" & $Daemon --sim --fastapi-host 127.0.0.1 --fastapi-port 8000 --no-goto-sleep-on-stop --dataset-update-interval 0 --no-preload-datasets

PASO 9.2 - COMPROBAR QUE OLLAMA RESPONDE
----------------------------------
Invoke-WebRequest http://127.0.0.1:11434/api/tags

PASO 9.3. PARCHE EN EL FORK LOCAL

Esto solo modifica la copia de prueba local, no Ahootsa.
$File = "D:\RITXI\pruebas_local_llm\reachy_mini_conversation_app_local\src\reachy_mini_conversation_app\main.py"
Copy-Item $File "$File.bak_$(Get-Date -Format yyyyMMdd_HHmmss)"
$txt = Get-Content $File -Raw
$txt = $txt.Replace(
'if robot.client.get_status()["simulation_enabled"] and not args.gradio:',
'if (not args.gradio) and bool(getattr(robot.client.get_status(), "simulation_enabled", False)):'
)
Set-Content $File $txt -Encoding UTF8

PARA CAMBIAR A ESTA LINEA EN EL MAIN.PY
if (not args.gradio) and bool(getattr(robot.client.get_status(), "simulation_enabled", False)):

2. Crear tus propios Wheels (Empaquetar tu aplicación)
Si modificas el código de la aplicación local de Reachy y quieres empaquetarla en un archivo .whl para instalársela al robot real o pasársela a otra persona, primero necesitas instalar una herramienta de construcción moderna llamada build:

PowerShell
uv pip install build
Y luego, situándote en la carpeta raíz del proyecto (donde está el archivo pyproject.toml o setup.py), ejecutas:

PowerShell
python -m build
Esto creará una carpeta llamada dist/ y dentro verás dos archivos; uno de ellos será el .whl de tu aplicación listo para distribuir.

3. Instalar en modo ejecutable/desarrollo (Lo que usa Reachy)
Cuando instalas la app del robot con el comando pip install -e ".", estás usando una función especial de setuptools y wheel llamada Editable Install.

En lugar de empaquetar un archivo .whl fijo y moverlo a las carpetas ocultas de Python, este comando crea un "enlace simbólico" hacia tu carpeta D:\RITXI\.... De esta forma, cualquier cambio que hagas en los archivos .py del código del robot se aplica al instante sin necesidad de volver a instalar nada.
